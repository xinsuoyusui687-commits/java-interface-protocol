# 字段证据与必填规则

## 字段的依据

字段可以来自用户协议、Java 字段声明、构造函数、对象创建、setter/getter、注释、注解、枚举、转换器或映射器。分别记录来源类别，不把以下几类合并为无来源的“完整字段列表”：

| 类别 | 能说明什么 |
| --- | --- |
| 协议定义 | 协议中列出，代码中可能未使用 |
| 代码声明 | 类中存在，当前调用链可能未赋值 |
| 代码赋值 | 当前调用链构建该字段；需记录条件分支 |
| 代码读取 | 当前代码读取该字段；不代表完整响应结构已知 |
| 外部依赖使用 | 当前项目使用此类型，但完整声明可能不可见 |

工作记录至少保留字段、完整类型、来源文件/类/方法、赋值或读取表达式、使用条件和证据范围。可以记录文件行号辅助定位，但不要把旧行号当成固定事实。

```text
Interface: 完整类名#方法
Object: 完整包名和泛型实参
Field: 字段名
Category: 协议定义 / 代码声明 / 代码赋值 / 代码读取 / 外部依赖使用
TypeEvidence: 字段声明或明确协议定义
RequiredEvidence: 协议标注或确认过的字段校验语义
SourceExpression: 赋值右侧表达式或读取位置
Condition: 实际分支条件；未知时说明
Location: 文件、类和方法
```

这是内部核对格式，不能机械增加到用户已有协议章节中。

## 类型

优先读取字段声明，结合 import、完整包名、父类和泛型实参确认。没有字段声明但协议明确类型时，保留协议类型并注明来源；只有 setter/getter 使用而无法确认声明时，不猜测精确类型。

- 保留 `List<Segment>`、`Map<String, String>` 和实际枚举名，不简化成 `array`、`Map` 或 `String`。
- 原 skill 主要处理 `private` 字段；Java 的其他访问级别或 record 组件同样以实际声明为依据，不能因不是 `private` 就认定字段不存在。
- 父类字段需要继续查看父类声明。父类或外部源码不可见时，不根据常见父类补字段。
- 协议名称与 Java 名称不同，先核对序列化注解和映射代码，记录两者关系；证据不足时询问，不静默改名。

## 必填标注

协议已明确 `Y/N/条件` 时保留原标注。协议与实现冲突时记录差异并确认，不覆盖任一来源来制造一致。

协议未标注时，检查字段声明上的校验注解及其实际定义。这里的 `Y/N` 是文档标注，不是已验证运行时校验生效；校验组或条件会改变结论时，记录适用条件。

| 已确认的声明或条件 | 标注 |
| --- | --- |
| `@NotNull` | `Y`：不能为 null |
| `@NotBlank` | `Y`：不能为 null 或空白字符串 |
| `@Valid` 或已确认等价的级联校验，且同时有 `@NotNull` | `Y`；存在时继续核对内部字段 |
| 只有 `@Valid` 或已确认的级联校验 | `N`：级联校验本身不等于对象必填 |
| 没有相关字段校验注解，且声明完整可见 | `N`：按本 skill 标注约定表示未发现字段声明层的必填约束，不保证服务端接受缺省值 |
| 字段或父类源码不可见、注解定义不明 | `代码无法确认` |

原 skill 还使用过 `@MinSize(value = 1)` 和 `@AssertValid` 约定。这些名称不应被当作通用 Jakarta Bean Validation 标准：

- 项目已确认 `@MinSize(value = 1)` 同时拒绝 null/缺省并要求至少一个元素时，可按原约定标 `Y`；如果只限制非 null 集合的长度，不据此判断必填。
- `@Size(min = 1)` 本身不能证明不允许 null；不能仅凭最小长度标 `Y`。
- 项目已确认 `@AssertValid` 仅表示级联校验时，单独出现按原约定标 `N`，配合 `@NotNull` 标 `Y`；含义未知时先确认注解定义或验证器。

不能因调用了 `setXxx()`、`getXxx()`，或字段是集合、对象、泛型就标 `Y`。代码中的显式拒绝逻辑可记录为使用条件或实现差异，不冒充字段声明注解。

## 字段来源追踪

例如 `request.setOrderNo(order.getOrderNo())` 只证明当前调用链从 `order.getOrderNo()` 赋值。继续确认 order 来自请求、数据库、配置、上下文还是其他数据源；不能仅凭变量名写成确定业务含义。

需要展开响应字段时，分别核对外层结果包装与业务 Response。源码声明、协议明示、具体读取或转换各自只证明相应部分。`return proxy.invoke(request)` 只说明透传，不能证明存在 success、code、message、data 等常见字段。

## 冲突与未知

以下情况应具体指出涉及字段和文件，再确认影响结论的选择：同名类位于不同包、协议和代码类型或嵌套关系不同、同一方法有不同构建分支、外部依赖不完整、必填性依据缺失、内部对象与资源侧对象的文档主体不明。

可使用“项目代码未声明”“项目代码未读取具体字段”“外部依赖源码不在当前仓库”“类型以外部依赖定义为准”“是否必填无法从当前代码确认”。已有协议但代码无法核验时，保留协议事实和来源范围，不强迫用户为每个已有协议字段重新确认。
