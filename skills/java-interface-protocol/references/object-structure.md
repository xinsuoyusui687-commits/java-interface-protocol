# 对象身份与层级规则

## 以完整类型识别对象

记录包名以及实际泛型参数。`com.example.web.OrderRequest` 与 `com.example.external.OrderRequest` 不能因简单类名相同而合并；不同泛型实参也不能未经核对共用一份具体字段定义。

建立父对象、字段、子对象类型及声明位置的关系，再分配文档编号，不根据对象出现顺序猜测层级。

## 按字段关系递归展开

- 自定义对象字段单独建表，不把子字段平铺进父表。
- `List<T>` 等集合按已确认的元素类型展开；泛型包装按实际参数解析。
- `Map<K,V>` 仅在代码或协议明确值对象结构时展开，不将任意 key 当作固定字段。
- 继承字段回到父类核对，记录声明来源；不要把继承关系误画成普通对象字段。
- Builder、Mapper、Converter 创建的对象，继续检查实际声明与构建逻辑。

例如源码确认：

```text
Response
└── result: List<Result>
    ├── segmentInfos: List<Segment>
    └── changeChargeInfos: List<ChangeChargeInfo>
        └── passengerCharges: List<PassengerCharge>
```

则对应编号为：

```text
1.2. Response
1.2.1. Result
1.2.1.1. Segment
1.2.1.2. ChangeChargeInfo
1.2.1.2.1. PassengerCharge
```

Markdown 标题同步递进：主请求/响应 `##`，直接子对象 `###`，孙对象 `####`。同一父对象的多个直接子对象使用连续同级编号。超过 Markdown 六级标题的深层结构，需采用目标格式支持的标题或先确认展示方式，不能把对象关系压成同级。

## 重复引用和循环引用

同一完整对象类型与相同泛型实参第一次完整展开，后续保留引用字段、类型和对象颜色，不再重复建表。循环引用同样终止于已有定义，避免无限递归。

在引用字段所属表格下标注：

```text
备注：
　　● StopInfo定义详见1.1.2.1
```

两个全角空格放在项目符号前。对象名和编号必须替换成实际首次定义，引用专用备注只写定义位置，不夹带证据解释。必要的其他说明另按用户模板处理，不与引用条目混写。

## 检查

每个可展开对象字段必须有子对象定义或有效引用；不可展开的外部类型应明确说明源码不可见。逐个确认直接父子只差一级、同级编号连续、所有“定义详见”可定位。已展开对象数、对象表数和合并表头数应一致；未展开的引用不计入新定义数量。
